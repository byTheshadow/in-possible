# 聊天上下文与提示词地基

这份文档是 in-possible 第一版聊天引擎的约束。先稳定上下文，再增加记忆、工具、提醒和主动消息。

## 一、数据归属

- `characters.bio`：角色核心身份与稳定人设。普通聊天不能随意改写。
- `characters.extraNotes`：角色补充细节，重要性低于核心身份。
- `chats.mode`：只属于一个聊天的模式：`roleplay` 或 `reality`。
- `chats.userProfile`：只属于一个聊天的用户资料。
- `chats.systemPrompt`：当前聊天的补充要求，不是最高优先级规则。
- `chats.reactionGuide`：当前聊天的回应风格建议。
- `chats.context`：上下文策略版本和稳定身份策略，由代码决定。
- `chats.permissions`：站内能力权限。权限决定能否调用能力，不代表能力已经执行。
- `memories`：已经整理出的长期记忆；`memoryCandidates`：等待确认的候选；`memoryRevisions`：修改历史；`memoryJobs`：每个聊天的提炼游标和任务状态。

新增字段必须通过读取默认值兼容旧记录；非查询字段不要新增索引。

## 二、上下文优先级

从高到低：

1. 应用级安全与诚实边界。
2. 角色核心身份与稳定设定。
3. 当前聊天模式。
4. 当前用户消息：决定本轮要回答的主题、问题和任务。
5. 当前聊天的用户资料。
6. 当前聊天的补充提示和回应风格。
7. 角色补充细节、记忆资料和最近历史消息。

“用户当前输入优先”只表示本轮回应要听用户在说什么，不表示用户可以通过一句普通消息把角色核心身份改掉。

## 三、两种模式

### 角色扮演模式

保留角色身份、口吻、故事连续性和世界观。角色可以进行虚构表达，但不能把已经发生的站外操作说成真的完成了。

### 现实模式

把对话当作现实中的陪伴和交流。可以保留角色的称呼和陪伴风格，但不把虚构设定当作现实事实；涉及现实世界的重要信息时要说明不确定性并建议核实。

两种模式共用一套聊天请求、历史记录和错误处理，但使用不同的模式规则段落。

## 四、当前阶段的边界

当前上下文管线已经预留并接入长期记忆层：聊天请求前按当前用户消息检索少量相关记忆；聊天结束后异步从新消息中提炼记忆，不阻塞正常回复。记忆是参考信息，不得覆盖当前用户明确更正的内容，也不得覆盖角色核心身份。

世界书、知识库、关系和 MCP 仍先保留数据接口，不假装已经参与上下文。WHEN-I-with-U 中与复杂应用绑定的情绪成长、导入导出和记忆管理界面暂不搬入。

主动消息、提醒和工具调用必须在权限通过后再接入；权限默认关闭，站内操作需要用户授权，向外发送或外部同步需要每次二次确认。

## 五、实现约束

统一从 `buildChatMessages` 进入，从 `buildSystemPrompt` 生成系统提示词。不要在 `ChatRoom`、调度器或具体工具里各自拼接另一套提示词。

任何提示词策略变化都要提升 `PROMPT_VERSION`，并在这里记录变化原因。
